# CLAUDE.md

## Project

Code Mode MCP server for Clever Cloud. Exposes the full Clever Cloud API (~245 commands) through three MCP tools (`search`, `execute`, `doc`) instead of one tool per endpoint. The agent writes JavaScript code that runs against a pre-authenticated `@clevercloud/client` instance, and can fetch Clever Cloud documentation on demand.

## Architecture

- `src/index.ts` — Entry point, wires McpServer with stdio transport
- `src/config.ts` — Reads `CLEVER_CLOUD_API_TOKEN` env var (required) and optional `CC_MCP_TIMEOUT_MS`, `CC_MCP_MAX_OUTPUT`, throwing on invalid values
- `src/client/create-client.ts` — Creates `CcApiClient` with API token auth and FileStore cache (XDG-compliant)
- `src/client/execution-client.ts` — Per-execution facade over the client: injects the execution signal into every request and closes the streams once the execution is over
- `src/tools/result.ts` — Builds every tool response: masks the API token, then cuts to the output budget
- `src/tools/search.ts` — MCP tool: text search over the command catalog (AND matching on terms), ranked and capped
- `src/tools/execute.ts` — MCP tool: runs JS code as an `AsyncFunction` body with `client`, `commands`, `console`, and `signal` (aborts on timeout or MCP cancellation) in scope
- `src/tools/doc.ts` — MCP tool: searches the Clever Cloud docs index (llms.txt, loaded on first use) or fetches a page as markdown via `Accept: text/markdown`
- `src/catalog/catalog.ts` — Types of the catalog entries
- `src/catalog/command-catalog.json` — **Generated file**: one entry per command with its description, endpoints, params, alternative required params and the named types they use
- `src/commands/command-registry.ts` — **Generated file**: static imports of all command classes into a flat record
- `scripts/generate-catalog.ts` — Generates both files above from the `@clevercloud/client` type declarations, through the TypeScript checker (`typescript/unstable/sync`)
- `test/` — `node:test` suites, with `.d.ts` fixtures for the generator in `test/fixtures/`
- `docs/adr-001-code-mode-pattern.md` — Architecture Decision Record explaining key design choices

## Key decisions

- No sandbox: runs locally, with the rights of the server process; single-user by design
- API token auth only (no OAuth v1)
- `AsyncFunction` executor; the timeout and MCP cancellation abort the client requests, not the code itself
- Command catalog generated by a script, committed to git, checked up to date by the CI
- All command classes eagerly loaded at startup

## Commands

```bash
npm clean-install         # Install the locked dependencies and build into dist/
npm run check             # Type check, build, then run the tests
npm run generate-catalog  # Regenerate catalog + registry from @clevercloud/client
npm start                 # Run the built MCP server (needs CLEVER_CLOUD_API_TOKEN)
node src/index.ts         # Run the MCP server from the sources
```

## Conventions

- Node.js 26 runs the TypeScript sources natively: relative imports use `.ts` extensions, only erasable syntax is allowed, and `tsc` rewrites the extensions when building (`tsconfig.build.json`)
- TypeScript strict mode with `noUncheckedIndexedAccess`, ESM (`"type": "module"`, `"module": "nodenext"`)
- Generated files (`command-catalog.json`, `command-registry.ts`) must not be edited manually — run `npm run generate-catalog` after upgrading `@clevercloud/client`
- Keep tool descriptions concise: they're injected into LLM context on every call
